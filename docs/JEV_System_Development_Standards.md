# JEV 系统开发规范总纲（V1）

## 💡 文档说明
本文档是 JEV 全栈自动化体系（desktopAgent.ps1、Cloudflare Worker、Tampermonkey 插件、TRAE 控制核心、Daojie CRM 接口）的通用技术标准。

## 📅 创建日期
$(Get-Date -Format "yyyy-MM-dd")

## 🎯 一、编码规范（Encoding Rules）
1. 所有文件 (.ps1, .js, .html, .json, .md) 均采用 UTF-8 without BOM。
2. 禁止使用 UTF-16、ANSI、UTF-8 with BOM。
3. PowerShell 文件在开头自动添加：
```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$PSDefaultParameterValues['Out-File:Encoding'] = 'utf8'
$OutputEncoding = [System.Text.Encoding]::UTF8
```
4. 所有 HTML 文件必须包含 `<meta charset="UTF-8">`。
5. 所有 HTTP 响应头需携带：`Content-Type: application/json; charset=utf-8`。
6. 若检测到 BOM 或其他编码，系统自动转换为 UTF-8 无 BOM。

## 🧩 二、命名规范（Naming Rules）
1. 文件命名统一使用 **小写字母 + 下划线**，示例：
   - `desktop_agent.ps1`
   - `jev_plugin_control.js`
   - `analyze_image_worker.js`
2. 变量与函数命名采用 **camelCase**，示例：
   - `getImageUrl()`  
   - `sendAgentCommand()`  
   - `updatePanelStatus()`
3. 类与构造函数使用 **PascalCase**，示例：
   - `class MessageHandler {}`  
   - `new FileUploader()`
4. 常量命名全大写，示例：
   - `API_BASE_URL`、`DEFAULT_TIMEOUT`
5. JSON 字段统一英文小写驼峰，禁止中文 key。

## ⚙️ 三、注释规范（Comments）
1. 所有函数必须写功能注释：
```js
// 功能：检测 Agent 状态并更新 UI
// 参数：status (string) - 当前连接状态
// 返回：void
```

2. PowerShell、JS 文件均要求首部包含文件说明、作者、版本、更新时间。
3. 禁止出现无意义的注释，如 "// test" 或 "// ok"。
4. 多行注释使用块结构：

   ```js
   /**
    * 说明：图片分析函数
    * 输入：图片URL
    * 输出：解析结果
    */
   ```

## 📡 四、API 通信规范（Protocol & API Rules）

1. 所有模块通信统一 JSON 协议：

   ```json
   {
     "success": true,
     "status": "ok",
     "data": {...},
     "timestamp": "2025-11-05T00:00:00Z"
   }
   ```
2. 所有请求需带头：

   * `Content-Type: application/json; charset=utf-8`
   * `Access-Control-Allow-Origin: *`
3. 字段命名统一驼峰：

   * `action`, `payload`, `source`, `timestamp`
4. 错误返回格式：

   ```json
   {
     "success": false,
     "error": "InvalidToken",
     "details": "Token expired or missing"
   }
   ```
5. 所有跨域 API 必须支持 `OPTIONS` 预检请求。
6. 所有 Agent 与 Worker 保留标准端口：

   * 1818 → 核心 Agent 通信；
   * 1819 → 控制面板；
   * Cloudflare Worker → `/ping` `/translate` `/analyze-image`。

## 📜 五、日志规范（Logging Rules）

1. 所有日志按统一格式输出：

   ```
   [2025-11-05 02:33:00] [Agent] 状态: 已连接
   [2025-11-05 02:34:12] [Worker] 翻译任务成功
   ```
2. 日志文件名统一：`logs/yyyy-MM-dd.log`
3. 错误日志分级：

   * INFO：普通运行；
   * WARN：非致命错误；
   * ERROR：严重异常；
   * FATAL：系统崩溃。
4. 重要操作需双写：

   * 控制台输出；
   * 文件写入。
5. TRAE 每日自动归档日志。

## 🧠 六、版本与变更规范（Versioning）

1. 所有脚本文件头包含版本号：
   `# Version: 1.0.0`
2. 每次修改必须更新版本号与变更说明。
3. 版本命名规则：

   * 主版本号：结构变动；
   * 次版本号：功能新增；
   * 修订号：Bug 修复。
4. 系统主版本号由 TRAE 统一管理。

## 🧩 八、代码生成与AI辅助规则

1. TRAE 或任何 AI 辅助生成的代码必须自动符合以上规范。
2. 若检测到编码错误、命名不合规、日志格式不匹配，自动修正并标记。
3. 所有自动生成文件附带标准化注释：
   `# Generated by TRAE under JEV System Standards`
