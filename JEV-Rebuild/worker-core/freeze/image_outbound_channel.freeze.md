# Image Outbound Channel - FREEZE RULE

## 1. 文件与功能定位

### 1.1 核心文件
- `worker-core/routes/daojie_pit_reply.js` - 图片发送通道实现

### 1.2 功能描述
该模块实现了图片消息的发送功能，打通了"我发送图片 → 客户真实收到图片"的完整链路，支持 WhatsApp 和 Instagram 平台。

## 2. 核心设计原则

### 2.1 独立物理通道
图片通道是独立的物理通道，与文本消息通道、AI通道、成交阶段模块等完全隔离。

### 2.2 严格的消息结构
图片消息必须遵循唯一标准结构：
```json
{ 
  "customer_id": "xxx", 
  "channel_id": 19 | 29, 
  "message_type": "image", 
  "image": { "url": "https://public-accessible-url.jpg" }, 
  "text": ""
}
```

### 2.3 平台特定实现
根据不同平台使用不同的图片发送结构：
- **WhatsApp (channel_id=19)**: `{ "image": { "link": "image_url" } }`
- **Instagram (channel_id=29)**: `{ "message": { "attachment": { "type": "image", "payload": { "url": "image_url" } } } }`

## 3. 允许的改动

1. **扩展平台支持**：在现有架构下新增其他平台的图片发送支持
2. **优化日志**：添加更详细的日志信息，便于调试和监控
3. **性能优化**：优化函数执行效率，不改变功能逻辑
4. **修复bug**：修复影响图片发送功能的bug
5. **升级依赖**：升级相关依赖库

## 4. 禁止的改动

1. **混用通道**：禁止将图片通道与文本消息通道、AI通道、成交阶段模块混用
2. **修改消息结构**：禁止修改图片消息的标准结构
3. **改变发送逻辑**：禁止改变现有图片发送的核心逻辑
4. **引入mock/fallback/simulate**：禁止引入任何模拟或回退机制
5. **把图片塞进text字段**：禁止将图片URL拼接到text字段中
6. **让AI参与图片发送**：禁止AI生成或处理图片消息
7. **改变现有inbox/pull行为**：禁止影响现有文本消息的拉取行为
8. **修改channel_id映射**：禁止修改WhatsApp=19、Instagram=29的映射关系

## 6. 验收标准

### 6.1 功能验收
- ✅ UI 能看到图片预览
- ✅ 刷新后图片仍存在
- ✅ 客户真实看到图片（不是链接）
- ✅ 文本通道完全不受影响
- ✅ AI 不读图片、不复述图片
- ✅ 不出现 role / direction 混乱
- ✅ 不出现 channel_id 错乱

### 6.2 日志验收
所有图片发送操作必须有完整的日志记录：
- `[OUTBOUND_IMAGE_PREPARED]`：图片准备发送
- `[OUTBOUND_IMAGE_PLATFORM]`：平台类型
- `[OUTBOUND_IMAGE_SENT]`：图片已发送
- `[OUTBOUND_IMAGE_URL]`：图片URL
