## 问题分析

通过分析代码，我发现OCR API 404错误的原因是：

1. **ImageOCRBlock.tsx中的API调用路径**：使用了相对路径 `/api/ocr/run` 和 `/api/ocr/result`，这会导致请求发送到当前域名，即 `http://localhost:3000/api/ocr/run`

2. **本地开发服务器未实现OCR API**：本地开发服务器 `http://localhost:3000` 没有实现 `/api/ocr/run` 和 `/api/ocr/result` 端点，因此返回404错误

3. **线上API地址未被使用**：虽然在 `jev_runtime_config.ts` 中已经配置了线上的API基础路径 `JEV_RUNTIME.API_BASE`，但是ImageOCRBlock.tsx没有使用这个配置

## 修复方案

1. **修改ImageOCRBlock.tsx中的API调用路径**：
   - 将相对路径 `/api/ocr/run` 改为使用线上地址 `${JEV_RUNTIME.API_BASE}/ocr/run`
   - 将相对路径 `/api/ocr/result` 改为使用线上地址 `${JEV_RUNTIME.API_BASE}/ocr/result`

2. **确保使用正确的线上API地址**：
   - 验证 `JEV_RUNTIME.API_BASE` 的值是否正确
   - 确保所有OCR相关的API调用都使用线上地址

3. **增强错误处理**：
   - 添加更多的日志记录，以便于调试和监控
   - 增加错误处理逻辑，确保在API调用失败时能够给出明确的错误提示

## 具体修改步骤

1. **修改ImageOCRBlock.tsx文件**：
   - 修改 `handleOCR` 函数中的API调用路径
   - 修改轮询OCR结果的API调用路径
   - 添加更多的日志记录，以便于调试和监控

2. **验证修复效果**：
   - 运行开发服务器，测试OCR功能是否正常工作
   - 检查浏览器控制台，确保没有404错误
   - 验证OCR API调用是否使用了线上地址

通过以上修改，应该能够解决OCR API 404错误，确保OCR功能能够正常工作。
