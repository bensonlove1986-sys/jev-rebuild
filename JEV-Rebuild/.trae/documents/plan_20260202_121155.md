# 实现翻译助手的客户语言自动锁定机制

## 需求分析

### 核心需求
- 按 chat_id 记忆客户语言，第一次选择语言后绑定到 chat_id
- 后续消息不再依赖 UI 当前选择，不受刷新/重载/切页面影响
- 永远使用该 chat_id 已锁定的语言
- 支持手动重新选择语言，覆盖旧锁定

## 实现计划

### 1. 修改 TranslationPlugin.tsx
- **更新接口**：修改 `TranslationPluginProps` 接口，添加 `chatId` 属性
- **添加状态**：添加 `chatLanguageMap` 状态，存储 chat_id 到目标语言的映射
- **修改逻辑**：
  - 首次翻译时，使用 UI 选择语言并存储到映射
  - 后续翻译时，使用映射中存储的语言，忽略 UI 选择
  - 添加语言覆盖机制，允许手动切换语言
- **更新调用**：修改 `translateMessage` 调用，传递 chat_id 和语言覆盖参数

### 2. 修改 translateService.ts
- **更新函数**：修改 `translateMessage` 函数，添加 `chatId`、`targetLanguage` 和 `languageOverride` 参数
- **更新 API 调用**：修改 `callTranslateAPI` 函数，传递这些新参数到后端

### 3. 修改 worker-core/index.js
- **更新端点**：修改 `/api/translate` 端点，添加对新参数的支持
- **实现逻辑**：
  - 解析 chat_id、target_language 和 language_override 参数
  - 实现语言锁定逻辑，优先使用已锁定的语言
  - 当 language_override=true 时，更新锁定的语言
  - 调用 DeepSeek API 时注入必要的参数

### 4. 修改 ChatComposer.tsx
- **传递属性**：修改 `TranslationPlugin` 组件调用，传递 `chatId` 属性

## 技术实现要点
- 使用映射表存储 chat_id 到目标语言的对应关系
- 优先使用已锁定的语言，忽略 UI 当前选择
- 提供手动覆盖机制，允许切换语言
- 确保语言锁定状态不受页面刷新或重载的影响
- 每次请求 DeepSeek 时注入必要的参数

## 预期效果
1. **首次翻译**：使用 UI 选择的语言，并锁定到 chat_id
2. **后续翻译**：使用已锁定的语言，不受 UI 选择的影响
3. **语言切换**：通过手动选择可以覆盖已锁定的语言
4. **状态保持**：语言锁定状态不受页面刷新或重载的影响
5. **独立性**：不同 chat_id 的语言锁定相互独立

## 实现步骤
1. 修改 `TranslationPlugin.tsx`，添加 chat_id 支持和语言锁定逻辑
2. 修改 `translateService.ts`，更新函数签名和 API 调用
3. 修改 `worker-core/index.js`，实现后端语言锁定逻辑
4. 修改 `ChatComposer.tsx`，传递 chat_id 属性
5. 测试功能，确保语言锁定机制正常工作
