# 问题分析

用户报告了一个严重问题：页面刷新后，自动发送的信息又重新发送了一堆。这是一个典型的页面刷新导致状态丢失和重复处理的问题。

## 可能的原因

1. **状态持久化问题**：页面刷新后，内存中的状态（如已处理的消息ID、正在处理的消息等）会丢失
2. **监听器注册问题**：页面刷新后可能会重新注册监听器，导致重复监听和处理消息
3. **去重机制问题**：虽然代码中有去重机制，但这些都是内存中的状态，页面刷新后会丢失
4. **持久化存储问题**：localStorage持久化可能存在数据不完整或加载不正确的问题
5. **全局单例问题**：页面刷新后，整个JavaScript环境重置，单例也会重新初始化

# 解决方案

## 1. 增强持久化存储

- **扩展持久化数据结构**：在localStorage中存储更完整的状态信息，包括：
  - 已处理的消息ID集合
  - 最后发送时间
  - 最后处理时间
  - 草稿处理状态

- **优化数据加载**：确保页面刷新后正确加载持久化数据到内存中

- **添加时间戳验证**：为持久化数据添加时间戳，确保只处理最近的消息

## 2. 改进去重机制

- **双重去重**：结合内存去重和持久化去重
  - 内存去重：使用现有的`processedInboundIdsRef`等内存状态
  - 持久化去重：使用localStorage存储已处理的消息ID

- **添加消息时间窗口**：只处理最近24小时内的消息，避免处理过期消息

- **增强发送锁**：使用持久化的发送锁，确保同一条消息不会被重复发送

## 3. 优化监听器注册

- **确保监听器唯一性**：使用更可靠的方式确保监听器只注册一次

- **添加监听器状态持久化**：记录监听器注册状态，避免重复注册

- **优化监听器清理**：确保组件卸载时正确清理监听器

## 4. 增强状态管理

- **改进全局单例初始化**：确保页面刷新后单例能够正确初始化并加载持久化数据

- **添加状态恢复机制**：页面刷新后，从持久化存储中恢复状态

- **优化状态同步**：确保内存状态和持久化状态的同步

## 5. 添加安全检查

- **添加消息方向检查**：确保只处理入站消息

- **添加消息类型检查**：确保只处理有效的消息类型

- **添加消息内容检查**：确保只处理有内容的消息

## 6. 优化日志记录

- **增强日志记录**：添加更详细的日志，便于调试和监控

- **添加错误处理**：确保系统能够优雅地处理错误，避免因错误导致的重复处理

## 7. 测试和验证

- **测试页面刷新场景**：确保页面刷新后系统不会重复处理消息

- **测试消息发送场景**：确保消息能够正确发送，不会重复发送

- **测试错误处理场景**：确保系统能够优雅地处理错误

# 具体实现步骤

1. **扩展持久化存储结构**：修改`getPersistentState`和`savePersistentState`函数
2. **改进去重机制**：结合内存去重和持久化去重
3. **优化监听器注册**：确保监听器只注册一次
4. **增强状态管理**：改进全局单例初始化和状态恢复
5. **添加安全检查**：添加消息方向、类型和内容检查
6. **优化日志记录**：添加更详细的日志
7. **测试和验证**：测试页面刷新、消息发送和错误处理场景

# 预期效果

- 页面刷新后，系统不会重复处理消息
- 消息能够按照倒计时正确发送，不会重复发送
- 系统能够优雅地处理错误，避免因错误导致的重复处理
- 系统能够正确显示AI建议回复和中文翻译
