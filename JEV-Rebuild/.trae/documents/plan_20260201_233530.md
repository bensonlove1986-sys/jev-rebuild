# 修复API URL重复拼接问题

## 问题分析

从错误信息中可以看到，API URL被严重重复拼接，导致连接失败：
- `https://jev-rebuild-worker.bensonlove1986.workers.dev/api/inbox/customershttps://jev-rebuild-worker.be…https://jev-rebuild-worker.be…`
- `https://jev-rebuild-worker.bensonlove1986.workers.dev/api/ws/chat/history?chat_id=whatsapp:+8615757759002https://jev-rebuild-worker.bensonlove1986.workers.dev/api/ws/chat/histor…https://jev-rebuild-worker.be…https://jev-rebuild-worker.be…`

这说明API_BASE_URL本身的值已经被污染，变成了一个重复拼接的URL，导致所有使用它构建的API URL都变得无效。

## 解决方案

### 1. 修改WhatsAppInboxService.ts文件

**问题**：
1. 在pullCustomerHistory和pullHistoricalMessages方法中，直接使用了`${this.API_BASE_URL}/api/ws/chat/history`的方式构建URL，没有使用normalizeApiUrl方法
2. normalizeApiUrl方法没有足够的保护措施来防止URL重复拼接

**解决方案**：
1. 修改pullCustomerHistory方法，使用normalizeApiUrl方法构建API URL
2. 修改pullHistoricalMessages方法，使用normalizeApiUrl方法构建API URL
3. 增强normalizeApiUrl方法，添加URL有效性检查，防止重复拼接
4. 增强API_BASE_URL的获取方法，添加检查，确保返回的URL是正确的

### 2. 修改config/api.ts文件

**问题**：API_BASE的获取没有验证和清理，直接使用环境变量的值

**解决方案**：在config/api.ts中添加API_BASE的验证和清理，确保它是一个有效的URL，没有重复拼接

## 修复步骤

### 1. 修改WhatsAppInboxService.ts文件

1. **修改pullCustomerHistory方法**：
   - 将`const historyUrl = `${this.API_BASE_URL}/api/ws/chat/history?chat_id=${chatId}``
   - 改为`const historyUrl = this.normalizeApiUrl(`/api/ws/chat/history?chat_id=${chatId}``

2. **修改pullHistoricalMessages方法**：
   - 将`const historyUrl = `${this.API_BASE_URL}/api/ws/chat/history``
   - 改为`const historyUrl = this.normalizeApiUrl('/api/ws/chat/history')`

3. **增强normalizeApiUrl方法**：
   - 添加URL有效性检查
   - 防止URL重复拼接
   - 确保返回的是一个有效的URL

4. **增强API_BASE_URL的获取方法**：
   - 添加检查，确保返回的URL是正确的
   - 防止返回重复拼接的URL

### 2. 修改config/api.ts文件

1. **添加API_BASE的验证和清理**：
   - 确保API_BASE是一个有效的URL
   - 清理重复拼接的部分
   - 确保返回的是一个干净的URL

- WebSocket连接成功
- 翻译功能正常工作
