# JEV L9.6 URL 双重拼接最终封锁补丁修复计划

## 目标
- UI 只允许发送相对路径
- Worker 只允许返回相对 media_path
- main.tsx 负责唯一拼接 BASE
- 发现第二个 https:// 必须立即截断

## 修复步骤

### 1. 更新 main.tsx 的 normalizeUrl 函数
- 替换为新的 normalizeUrl 函数，确保：
  - 发现第二个 https:// 立即截断
  - 绝对 URL 直接放行
  - 清理 /api/api 重复
  - 强制补 /
  - 唯一拼接 BASE
  - 添加必要的日志打印

### 2. 修复 UI 层的绝对 URL 使用
- **ChatLayout.tsx**: 移除 WORKER_ORIGIN 使用，改为相对路径
- **useAutoDraftEngine.ts**: 确保使用相对路径 `/api/draft/generate`
- **contactStore.ts**: 确保使用相对路径 `/api/inbox/list`
- **WhatsAppInboxService.ts**: 确保使用相对路径 `/api/contact/upsert`
- **ui_scheduler_core.ts**: 确保使用相对路径

### 3. 确保 Worker 端返回相对 media_path
- 检查所有 Worker 端返回 media_path 的地方
- 确保返回的是相对路径 `/api/media/r2/whatsapp/${message_id}/${media_id}`
- 添加 `[MEDIA_PATH_RELATIVE_OK]` 日志

### 4. 添加 media_path 污染修复逻辑
- 在 WhatsAppInboxService.validateMediaPath 中添加：
  - 检查 mediaPath 是否包含多个 https://
  - 如果是，截断到第一个 /api/media/r2/ 开始的部分
  - 添加 `[MEDIA_PATH_CORRUPTED_FIXED]` 日志

### 5. 验证修复效果
- 确保不再出现 `/api/api/`、`https://...https://...`、`MMhttps://`
- 验证验收日志：
  1. `[AUTO_DRAFT_API_URL] /api/draft/generate`
  2. `[FETCH_URL_FINAL_SAFE] https://jev-rebuild-worker.bensonlove1986.workers.dev/api/draft/generate`
  3. `[MEDIA_PATH_RELATIVE_OK] /api/media/r2/...`

## 执行边界
- 不修改部署目标
- 不修改域名
- 不新增 mock 逻辑
- 只修 URL 构造链路与 media_path 污染
