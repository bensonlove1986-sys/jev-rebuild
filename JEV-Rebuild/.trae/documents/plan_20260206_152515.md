# JEV L9.6 URL Root Seal v2 修复计划

## 目标
- 禁止任何位置返回/携带完整域名
- 只允许 main.tsx fetch wrapper 拼 BASE
- 修复 media_path 污染问题
- 彻底封死二次拼接

## 修复步骤

### 1. 更新 main.tsx 的 normalizeUrl 函数
- 添加二次拼接熔断逻辑：发现包含第二个 `https://` 时直接截断
- 确保完整 URL 直接放行且禁止再次 append
- 清理 `/api/api` 重复
- 添加必要的日志打印：raw、finalURL、[URL_ABSOLUTE_PASSTHROUGH]
- 固定 BASE 为 `https://jev-rebuild-worker.bensonlove1986.workers.dev`

### 2. 修复 useAutoDraftEngine.ts
- 将 `const apiUrl = buildApiUrl('/api/draft/generate');` 改为 `const apiUrl = '/api/draft/generate';`
- 确保不再使用 `buildApiUrl` 函数构建 API URL

### 3. 修复 Worker 端的 media_path 返回格式
- 找到所有返回 media_path 的地方
- 确保返回相对路径 `/api/media/r2/...` 而不是完整 URL
- 添加 `[MEDIA_PATH_RELATIVE_OK]` 日志

### 4. 验证修复效果
- 确保不再出现 `/api/api/` 重复
- 确保 media_path 始终是相对路径
- 确保只有 main.tsx fetch wrapper 在拼接 BASE URL
- 验证验收标准：
  1. `[AUTO_DRAFT_API_URL] /api/draft/generate`
  2. `[FETCH_URL_FINAL_SAFE] https://jev-rebuild-worker.bensonlove1986.workers.dev/api/draft/generate`
  3. `[MEDIA_PATH_RELATIVE_OK] /api/media/r2/whatsapp/MM.../ME...`

## 执行边界
- 不改域名、不改部署、不改路径命名
- 只修 URL 构造与消息字段污染
- 不新增 mock，只做截断/放行/相对化的存在性修复
