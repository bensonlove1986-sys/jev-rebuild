# 修复翻译插件的三个问题

## 问题分析

### 1. 拖动有明显卡顿
- **原因**：每次鼠标移动都会触发 setState，导致 React 组件重新渲染，引起卡顿
- **影响**：用户体验差，拖动不流畅

### 2. 原文不能输入文字
- **原因**：翻译弹窗中的原文区域只是显示 inputText，没有提供输入功能
- **影响**：用户只能在聊天输入框中输入文字，然后在翻译弹窗中查看翻译结果，操作不便

### 3. 翻译方向问题
- **原因**：当前翻译服务总是将文本翻译成中文（target: 'zh-CN'），而不是将中文翻译成客户的语言
- **影响**：无法实现将中文翻译成其他语言发送给客户的功能

## 修复计划

### 1. 优化拖动性能
- **实现**：使用 useRef 存储拖动状态，在拖动过程中直接修改 DOM 样式，只在拖动结束时更新组件状态
- **文件**：`TranslationPlugin.tsx`
- **关键修改**：
  - 添加拖动状态的 ref
  - 修改 handleDragMove 函数，使用 requestAnimationFrame 优化
  - 只在拖动结束时调用 setState 更新位置

### 2. 添加原文输入功能
- **实现**：在翻译弹窗中添加文本输入框，允许用户直接输入原文
- **文件**：
  - `TranslationPlugin.tsx`：添加本地输入状态和处理函数
  - `TranslationPopup.tsx`：添加输入框组件
- **关键修改**：
  - 添加 localInputText 状态
  - 修改 TranslationPopupProps，添加 onInputChange 属性
  - 在原文区域添加 textarea 输入框

### 3. 修复翻译方向
- **实现**：修改翻译服务，使其能够根据选择的语言进行翻译
- **文件**：
  - `TranslationPlugin.tsx`：修改翻译调用，传递目标语言
  - `translateService.ts`：修改 API 调用，传递目标语言参数
- **关键修改**：
  - 修改 debouncedTranslate 函数，传递 selectedLanguage.code
  - 修改 callTranslateAPI 函数，添加 target_lang 参数
  - 修改翻译 API 请求，包含目标语言

## 预期效果

1. **拖动流畅**：翻译助手可以流畅拖动，无明显卡顿
2. **原文可编辑**：用户可以直接在翻译弹窗中输入原文
3. **翻译方向正确**：将中文翻译成选择的目标语言，实现与客户的多语言交流

## 技术要点

- 使用 useRef 和 requestAnimationFrame 优化拖动性能
- 实现双向数据绑定，同步原文输入
- 调整翻译服务的 API 调用，支持目标语言参数
- 确保修改后的代码与现有架构兼容
