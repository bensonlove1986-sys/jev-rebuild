## 问题分析
用户反馈自动回复的时间设置与倒计时显示的时间不匹配，需要确保两者保持一致。

## 根本原因
1. **状态管理不一致**：`fixedReplyTime` 是本地状态，而非从 store 获取
2. **计算逻辑差异**：倒计时使用 `actualDelay`，会被调整为至少 2 秒
3. **UI 显示不直观**：用户设置的时间与实际倒计时时间不同步

## 修复方案

### 1. 统一状态管理
- 将 `fixedReplyTime`、`useRandomReplyTime`、`minRandomTime`、`maxRandomTime` 移至 `autoEngineStore`
- 添加相应的 setter 方法
- 确保 UI 控件直接读写 store 状态

### 2. 优化倒计时计算
- 保持最小间隔 2 秒的逻辑
- 但在 UI 显示上保持与用户设置一致
- 添加明确的日志说明实际使用的延迟时间

### 3. 增强 UI 反馈
- 在倒计时显示中添加提示，说明实际延迟可能会因最近发送而调整
- 确保滑块值与显示值实时同步
- 添加设置保存的视觉反馈

### 4. 代码修改
- **autoEngineStore.ts**：添加回复时间相关状态和 setter
- **DeepSeekPanel.tsx**：修改为使用 store 中的回复时间状态
- **useAutoDraftEngine.ts**：确保使用最新的 store 状态进行计算

### 5. 验证测试
- 测试不同回复时间设置下的倒计时显示
- 验证快速连续消息时的延迟调整逻辑
- 确保 UI 控件与 store 状态同步

## 预期结果
- 回复时间设置与倒计时显示保持一致
- 用户可以清晰了解实际使用的延迟时间
- 保持系统的稳定性和可靠性
